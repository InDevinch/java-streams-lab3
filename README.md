# Лабораторна робота 3 — Stream API, Optional та Gatherer

Індевич Олег, ІК-42. Варіант 2: N = 5, 5 mod 3 = 2.

`SecurityLogAnalyzer` обробляє потоки безпекових подій:
- `findFirstCriticalEvent` повертає Optional першої події CRITICAL;
- `getLogsBeforeDeadline` використовує takeWhile для впорядкованого за часом потоку; подія рівно на deadline не входить;
- `detectIpBursts` використовує власний послідовний Gatherer і limit для обмеження кількості результатів.

Сплеск — максимальна безперервна серія з одного IP довжиною не менше burstThreshold. Вона видається один раз, у момент досягнення порогу. Якщо після іншого IP той самий IP знову формує серію, це новий сплеск. Ліміт рахує сплески, а не глобально унікальні IP. Саме цю інтерпретацію перевіряють тести.

Обов'язкові параметри null і непозитивні числові параметри відхиляються через IllegalArgumentException. Елементи потоку мають бути коректними SecurityLog з непорожнім IP та ненульовим timestamp. Самі потоки методи не закривають: ресурси контролює їхній власник.

## Запуск

Потрібна Java 25 для компіляції (Gatherer є стабільним API починаючи з Java 24). Gradle Wrapper і Foojay завантажують JDK 25 автоматично; для запуску Gradle достатньо JDK 17+ та доступу до інтернету при першій збірці.

Windows:

```powershell
.\gradlew.bat clean test
.\gradlew.bat run
```

Linux/macOS:

```sh
./gradlew clean test
./gradlew run
```

Версії залежностей містяться в gradle/libs.versions.toml. Звіт тестів: build/reports/tests/test/index.html.

Тести мають @Timeout(2) і перевіряють скінченні та нескінченні потоки, порядок, межу часу, стан Gatherer, Optional.empty, null і непозитивні параметри. Лічильники спожитих подій перевіряють short-circuiting без зайвого читання.

Демо використовує Stream.iterate без limit на джерелі. Завершення забезпечують findFirst, takeWhile і gather(...).limit(...). Для нескінченного потоку без шуканої події або без достатньої кількості сплесків результат закономірно не може бути завершений; у тестах завершення забезпечують дані.
